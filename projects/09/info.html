How it works · Project 09

Pixel Racer

A PS1-style arcade racer with bots and room-code multiplayer, all in the browser.

What it is

Pick a pixel-art car, pick a map and drive. Race bots or up to 8 players in a room. Four maps: a 800-metre Chicago sprint and three classic Need for Speed III circuits (Country Woods, Lost Canyons, Rocky Pass). Keyboard, touch or gamepad.

How it loads

  • Only the selected map and the selected car load at first. A map is fetched when you pick it and kept in memory, so switching back is instant. A failed load clears itself so you can retry.
  • Maps are loaded with GLTFLoader and the meshopt decoder, then merged to one mesh per material to keep the number of draw calls low. Unlit maps use basic materials, the lit NFS III maps use Lambert.
  • Collision is built from the same meshes you see: flat triangles are ground, steep ones become wall segments. Trees and fences only block where their texture is solid.
  • Texture size is reduced at runtime on phones (auto picks 512 px on touch devices). Settings: pixel size, texture size, car filter, anisotropy, draw distance, wheel spin, sound, music, mirror. Saved in localStorage as pixel-racer-settings.
  • The big GLB files are in the offline "heavy" list: saved the first time they are used, or all at once with the Save everything button on the main page.

Racing rules

  • Race types: Sprint (default, half the route), full route, N laps, or free roam (laps are timed but nothing ends). A 3-second countdown with start lights comes first.
  • A track is a centre line resampled every 4 m with a gate roughly every 150 m. Gates must be passed in order, so reversing over the line or cutting across the infield does not count a lap.
  • A wrong-way warning appears after 1 second pointing back along the road.
  • Ranking: finishers by time, everyone else by progress along the track.
  • Bots follow a racing line relaxed up to 6 m to each side of the centre, and reverse out when stuck.

How multiplayer works here

Both games use PeerJS (a small helper around WebRTC) to connect players straight to each other. There is no game server of our own.

Joining by room code

  1. The host taps Host. The game makes a random 5-character code (letters and digits without I, L, O, 0 and 1, so it is easy to read out loud) and registers it with the free PeerJS cloud under an id such as lpstrike-K7QM2 (08) or pxracer-K7QM2 (09).
  2. A friend types the code (or scans the QR code, see below). Their browser asks PeerJS for that id. PeerJS only passes the connection details (the "signalling" step) and then steps out of the way.
  3. The two browsers now talk directly over WebRTC data channels. If a direct path is impossible (strict network), PeerJS cloud also offers a relay (TURN) as a fallback.
  4. The friend sends hello with their name. The host must receive it within 5 seconds or the link is dropped.

Two channels per player

ChannelTypeCarries
relOrdered and reliablehello, welcome, lobby, roster, start, map choice, buy, team, heartbeat, bye
fastUnordered, no resends (maxRetransmits: 0)Inputs and snapshots (08), car states (09). A late packet is useless, so it is never re-sent.

The joiner opens fast once rel is up. If fast never opens, everything falls back to rel: slower, but it still works.

Health checks

  • A heartbeat every 2 seconds. A link with no data for 6 seconds is closed. The round-trip time (ping) is smoothed and shown.
  • Joiner loses the host: "Lost connection to the host" and back to the menu. Host leaves: everybody is told "The host closed the game". There is no host migration.
  • The PeerJS library is loaded only when someone hosts or joins (a local copy, no CDN).

QR code and links

  • The host lobby shows a QR code that contains a link like .../projects/08/index.html?join=K7QM2.
  • Scanning it with any phone camera opens the game with the code filled in, and it joins automatically.
  • The join screen also has a Scan QR code button that reads the code with the camera. It only appears in browsers that support BarcodeDetector (Android Chrome, macOS). On iPhone and Windows Chrome use the camera app or type the code.
  • The QR link uses the address the page was opened from, so open the game from the real website (not localhost) when hosting for friends.
  • Files: qrcode.js draws the code, joinqr.js has draw, scan and codeFrom.

Test knobs (URL)

  • ?lag=120 delays everything this tab sends by 120 ms. ?loss=5 drops 5% of the fast packets. Browser DevTools throttling does not touch WebRTC, so use these to test bad connections.

Different from Low-Poly Strike

  • Every player drives their own car locally, so there is no input lag. Each peer sends its car state (position, yaw, pitch, roll, speed, steering) about 20 times a second on the fast channel.
  • The host keeps the roster, runs the bots, and sends everyone one snapshot about 20 times a second with every other car. Remote cars are drawn about 110 ms in the past and smoothed. A jump over 15 m counts as a reset and snaps.
  • Cars only push themselves out of each other. Nobody waits for anybody and nothing is predicted or lag-compensated.
  • Race sync: the host starts the race and sends the milliseconds until the lights go green (each client subtracts half its ping). Each player counts their own laps and reports them; the host merges bots, itself and the reports and sends the ranking in every snapshot. Late joiners sit the race out. Going to the garage cancels the race for everyone.
  • The host chooses the map for the whole room. Room size is chosen by the host: 4, 6 or 8 players.

Adding a car or a map

  • Car: drop a .glb in models/ and add an entry in cars.js (real length in metres, wheel handling, forward axis). Add it to the offline heavy list by rebuilding the manifest.
  • Map: add the .glb in maps/, a definition in maps.js (file, scale, spawn, road width, sky, fog), and a centre line in tracks.js if you want races. A map without a centre line is free roam only.
  • Run python tools/build_offline_manifest.py afterwards.

How it differs from the other projects

  • Same connection code as Low-Poly Strike, but a simpler, more forgiving model: each driver is the authority for their own car.
  • Heavy assets (3D maps and cars) loaded on demand, with collision derived from the render meshes at load; Strike keeps separate hand-built collision boxes.
  • Supports gamepad and has many URL options for quick testing.

Main quality

Smooth, forgiving multiplayer racing with real 3D tracks and a deliberately chunky PS1 look, in a static website.
