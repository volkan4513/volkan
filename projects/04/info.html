PS Music Player

A PlayStation-inspired pixel-art music player.

What it is

A music player drawn like a PlayStation: a pixel disc that spins, a visualizer, lyrics, a local playlist and live search of iTunes 30-second previews.

Files and loading

FileRole
index.htmlThe whole player: layout, canvas drawing, playback, search, lyrics.
playlist.jsThe built-in songs (hardcodedMusicData). Also used by the small player on the main page.
music/*.mp37 songs (heavy files, cached on first play or by Save everything).
music/cover/*.webpCover art for each song.
  • Outside services: the iTunes Search API (previews) and api.lyrics.ovh (lyrics). Those go straight to the network, never through the offline cache.

How it works

  • Pixel covers: pixelate() shrinks the cover, makes the edges hard and reduces the colours with a 4×4 Bayer ordered dither.
  • Spinning disc: the cover is clipped to a disc and rotated inside a tiny canvas with nearest-neighbour sampling, redrawn at 15 frames per second so it keeps the chunky look.
  • Song change: the lid and parts slide down, the next song loads, and they slide back. The page background is tinted from the cover's average colour.
  • Visualizer: for local songs it uses real frequency data from a Web Audio AnalyserNode. iTunes previews are cross-origin, so they get a fake bouncing animation instead.

Adding songs

  • Put the mp3 in music/ and a cover in music/cover/ with the same base name, add an entry in playlist.js, then run python tools/build_offline_manifest.py.

Screen layers and the disc

  • The device is five stacked canvases (layer1-layer5) built by initDevice() from ps_player_images/: ps_front_cover.webp, ps_disk_cover.webp (the lid), cover_image_outter_part.png, ps_empty_disk.webp, ps_disk_back.webp. Each is pixelated to 160×160 (DEV) with 7 colour levels and fit: 'contain'.
  • ps_default_disk_00.webp is the disc-shaped mask and also the fallback art. setDiskArt() pixelates the cover at 160 px with 6 levels (cover fit), then clips it to the mask with destination-in.
  • pixelate(url, size, {levels, fit}): draws the image centred, then sets each pixel's alpha to 0 if it is under 128 and 255 otherwise, and adds the Bayer value times the step (255/(levels-1)) before rounding each channel to the nearest step. If the pixels cannot be read (cross-origin art without CORS) the plain downscale is kept. Remote images are first tried with crossOrigin=anonymous and retried without it.
  • Spin: a frame is skipped unless 1/15 s has passed; the angle grows by π/24 per step (7.5 degrees, 48 steps per turn). Rotation uses imageSmoothingEnabled = false. The angle resets to 0 on each song load, and the loop is cancelled on pause.
  • Song swap (transitionTo): pause, lid slides down (wait 160 ms), disc and inner layers slide down (320 ms), the new song loads, the parts slide back (320 ms), the lid closes (300 ms). A switching flag ignores clicks and keys during the animation. With prefers-reduced-motion the CSS durations drop to 0.01 ms.
  • Background tint: tintFrom() samples every 4th pixel of the 32 px thumbnail, ignores transparent and very dark or light ones (brightness 25-225), averages the colour and sets --bg to 30% of it.

Audio engine

  • Two <audio> tags, both preload="none": audio for local files and remoteAudio for iTunes. The variable audio points at the active one; events of the other are ignored (live() check). Volume and mute are applied to both.
  • Local file names go through encodeURI with # replaced by %23, so names with spaces or dots work.
  • The Web Audio graph (MediaElementSource of the local tag, to an AnalyserNode with fftSize 64, to the speakers) is created lazily on the first local play, inside the click or key handler, and resumed if suspended. If creation fails the analyser is null and the fake animation is used. Remote previews are not routed through it.
  • Visualizer: 24 bars drawn pixel row by pixel row; green below 45% of the height, yellow up to 75%, red above. Real data is getByteFrequencyData (first 24 of 32 bins). Otherwise: a sine bounce when playing, a flat 4% when paused. Drawing stops while document.hidden.
  • Progress slider: 0-100; dragging sets currentTime as a percentage of duration (ignored until the duration is known). Time text is m:ss, or 0:00 when the duration is not finite.
  • The loader shows on waiting and hides on playing, canplay, error, stalled and pause.
  • If play() is rejected (autoplay policy) a warning is logged, isPlaying stays false and the icon shows Play. The first song is loaded on boot but never auto-played.

Playlist and library details

  • LOCAL: initPlaylist() maps hardcodedMusicData. The cover path comes from the mp3 file name: music/cover/<base name>.webp. A missing title becomes the file name with underscores as spaces, a missing artist becomes "Unknown Artist", a missing genre becomes "Other". The list is headed MEMORY CARD 1. The playlist currently has 7 entries.
  • ITUNES: switching tabs pauses playback, clears the search box and genre filter, closes the lyrics panel and shows a hint. Typing restarts a 600 ms timer, then requests itunes.apple.com/search?media=music&entity=song&limit=25. Results without a previewUrl are dropped. Artwork 100x100bb is swapped to 300x300bb. Rows get a "30S" badge instead of a number. Messages: NO RESULTS FOUND, SEARCH FAILED (check your connection), TYPE TO SEARCH ITUNES. Going back to LOCAL rebuilds the playlist from playlist.js.
  • Genre filter buttons are generated from each song's genre and appear only when there are at least 2 genres (the local list has one, so none show). iTunes results use primaryGenreName. The local search box matches title, artist and album text; the counter shows "N SONGS".
  • Row thumbnails are 32 px pixelated covers (5 levels), cached in a Map by cover URL, with the default disc as fallback. Clicking the current row toggles play/pause; clicking another row swaps to it and plays.
  • Shuffle picks a random index and, if it equals the current song, takes the next one instead. Previous always goes back one in list order. Repeat only restarts the current song when it ends; Next still moves on.
  • Nothing is saved: no localStorage, no URL options. Volume, shuffle, repeat and mute reset on reload.

Lyrics, toast and mobile layout

  • Lyrics come from api.lyrics.ovh/v1/<artist>/<title>, fetched only when the panel opens (button or L) and again on each song change while it is open. It shows LOADING..., then the text, or NO LYRICS FOUND FOR THIS SONG. on any error or empty reply. Titles are sent as stored, so tags like "(Daytime)" or "Remix" can make a match fail.
  • A toast with the 32 px cover, title and artist appears when playback starts and hides after 3.2 s. A long title scrolls only when it is wider than its box, re-checked on window resize.
  • Volume steps are 0.1 (buttons and Up/Down), clamped to 0-1. Mute toggles both audio tags.
  • Phones (max-width 900 px): one column, a compact player on top and the track list in a 50dvh row, so it always gets half the screen and scrolls by itself. On short phones (max-height 720 px) the cover size is min(23vh, 175px, 39vw). Safe-area insets are respected.

How it differs from the other projects

Audio-first: it uses the Web Audio API and two outside web services, and its visual identity is hand-built pixel-art canvases.

Main quality

A convincing pixel-art device skin where cover art is dithered live and the disc turns in 15 fps steps.
