How it works · Project 06

Parking Puzzle

Pixel-art sliding-block puzzle, with its own level builder and sprite editor.

What it is

A Rush-Hour style puzzle. Every car slides only along its own axis (horizontal cars left and right, vertical cars up and down). Free the red car by driving it out of the right edge. There are 20 levels, a par (best possible move count) for each, stars, a timer and a daily puzzle shared by everyone.

Three tools make up the project: the game (index.html), the level builder (builder.html, which also holds the sprite editor), and two Python tools in tools/ that solve levels and rebuild the sprite sheet.

How it loads

  • The game fetches tiles.json on start. Levels play in array order, so adding a level to the file is all the game needs.
  • Start level is the last one you played (saved in the browser). ?daily jumps to today's level. ?level=N opens level N (1-based).
  • Cell size is worked out from the screen (maximum 104px, snapped to whole device pixels so the pixel art stays sharp).
  • The main page draws today's board on a small canvas from the same tiles.json and the same pixel sheet.
  • Everything is cached by the service worker, so the puzzle works offline after the first visit.
  • The old address page2.html still works: it is a small redirect to projects/06/index.html and keeps ?daily and ?level=.

Rules, par and stars

  • Win: the red car's right edge reaches the right edge of the board (it must be a horizontal car).
  • Moves: several moves in a row with the same car count as one move. The solver uses exactly the same rule, so par is the true minimum.
  • Stars: 3 stars if moves ≤ par. 2 stars if moves ≤ par + half of par (rounded up). Otherwise 1 star. A level with no par always gives 3 stars.
  • Best result per level (most stars, then fewest moves) is stored in the browser.
  • Timer: 90 seconds, started by your first move. After 20 seconds of struggling a funny toast appears, then another every 8 seconds.
  • Switching tabs pauses the timer.

Daily puzzle

Daily.index(total) returns (dayNumber * 7 + 3) % total. Everybody gets the same level on the same day, and because 7 shares no factor with 20, every level comes up exactly once per cycle.

Finishing today's level (opened with ?daily) calls Daily.record(moves, stars): the streak goes up by 1 if you also played yesterday, otherwise it restarts at 1. Only your lowest-move result for the day is kept, and the last 40 days are remembered.

Saved in this browser only: localStorage keys parking-puzzle-progress (best results and last level) and parking-daily (streak and daily results).

Making a new level (the whole workflow)

This is the part to use when you have a new idea for a level.

  1. Start a local server in the project folder, for example python -m http.server 8765, and open http://127.0.0.1:8765/projects/06/builder.html. The builder needs a server because it fetches tiles.json.
  2. Click + Add Level. A new empty level is created with the current grid size. Set Columns and Rows (2 to 20) if you want a different board.
  3. Click an empty cell to open Add Tile. Choose width and height (a normal car is 1×2 or 1×3 cells), direction, colour and, optionally, a vehicle sprite. Picking a sprite fills in the size and direction for you.
  4. Place the red car: tick Win tile (exits right) on exactly one horizontal car, and put it on the row that reaches the right edge.
  5. Click an existing car to edit or delete it. Copy then click an empty cell to paste a copy. Copy Level lets you paste a level over another or as a new level.
  6. Drag the level tabs to reorder levels. The ✕ on a tab deletes a level.
  7. Click Save (download tiles.json). Replace projects/06/tiles.json in the repo with the downloaded file.
  8. Run python tools/gen_levels.py. It solves every level, writes each level's par, and prints UNSOLVABLE for any level that cannot be won. Fix those in the builder and repeat.
  9. Open projects/06/index.html?level=N (N is the level number) and play it. Rebuild the offline manifest (python tools/build_offline_manifest.py) before deploying so the new data is cached.
The builder does not check your level. It only stops overlapping cars and cars outside the grid. It does not check that there is exactly one red car, that the red car is horizontal, that the level can be solved, or what the par is. Always run gen_levels.py after saving.
Progress is stored by level name. Levels are renamed level1 … levelN in order, so reordering or deleting levels moves saved stars and best results to different levels.
Hard levels come from many blocking cars and a long chain of moves, not from a big board. gen_levels.py --add 10 can invent new ones for you; open them in the builder to tweak.

The sprite editor

A sprite is a rectangle of cells cut from the big car picture. Each car in a level can point at one sprite by number (spriteIndex). Cars without a sprite are drawn as a flat colour block.

Using it

  1. In the builder, click Manage Sprites. A full-screen panel shows tiles_texture.webp with a grid of 80px cells over it.
  2. Click one cell to start a selection. Shift, Ctrl or Cmd + click another cell to stretch it into a rectangle. Selected cells turn green. Cells with a cyan border are already part of a saved sprite.
  3. The label shows the size, for example 2 x 1 cells.
  4. Set Native direction of selected art: Horizontal if the car is drawn lying sideways, Vertical if it is drawn standing up.
  5. Click Save Sprite. It is added to the list with a thumbnail and a number (#idx: WxH (direction)). Clear Selection cancels.
  6. The ✕ beside a sprite deletes it. Close the panel, then pick the new sprite in the Add Tile or Edit popup.
  7. Save tiles.json as usual.

Making the new sprite show up in the game

The game does not read the big .webp. It reads the 16px pixel sheet. After you change the artwork or add sprites, run:

python tools/pixelate_tiles.py
  • It needs the Pillow library. It averages each 5×5 block (80px becomes 16px) and reduces the picture to 28 colours.
  • It keeps only the largest shape inside each sprite rectangle (this removes stray specks) and adds a 1px dark outline.
  • Cells that are not inside any sprite rectangle become transparent in the output, so a new sprite must be saved in the editor before you run the tool.
  • The sheet must stay 6 cells wide and 12 cells tall (SHEET_COLS and SHEET_ROWS in the game). Putting art outside that grid will not show.

How a sprite is matched to a car

  • A car's width and height should equal the sprite's footprint. If the car's direction differs from the sprite's native direction, the picture is rotated 90 degrees automatically.
  • Convention used by the level generator: sprite 0 is the red car, 1-8 are 2-cell horizontal cars, 9-12 are 3-cell horizontal, 16-19 are 2-cell vertical, 20-22 are 3-cell vertical. New sprites added at the end of the list keep these numbers safe.
Deleting a sprite renumbers every sprite after it. Cars that used the later sprites are not updated, so existing levels will show the wrong cars. Prefer adding sprites at the end and leaving old ones in place.

How the solver and generator work

tools/gen_levels.py treats each level as a state of car positions along their own lines.

  • Solve: breadth-first search. One step slides one car any distance, which matches the game's "same car in a row is one move" rule. The fewest steps to get the red car out is the par. If no way out exists, the level is reported as unsolvable.
  • Generate: hill-climbing. Start from an existing level (or a lone red car), then repeatedly add, remove or replace a car. Keep a change when the par goes up (or sometimes when it stays equal). Restart after 600 steps without progress. It stops at the target par or after about 75 seconds.
  • Generated levels cycle through board sizes 6×6, 6×7, 6×6 and 7×7. New cars get random colours and matching sprites.
python tools/gen_levels.py                 # check all levels, rewrite par
python tools/gen_levels.py --add 10           # also append 10 generated levels
python tools/gen_levels.py --add 10 --seed 7  # repeatable
The tool rewrites projects/06/tiles.json in place and needs every level to have a red car. Commit or copy the file first.

How it differs from the other projects

  • The only project driven entirely by a data file (tiles.json) plus its own authoring tools.
  • Uses a real solver (Python) to guarantee levels are winnable and to set par; the games in 08 and 09 have no such tooling.
  • Pure DOM and CSS pixel art with pointer events, no canvas and no 3D library. The main page borrows its data and sprite sheet for the daily card.

Main quality

Small, handmade and endlessly extendable: a new level is a few clicks in the builder plus one command, and the solver tells you how hard it really is.
