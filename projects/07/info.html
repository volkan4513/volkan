How it works · Project 07

Widget Desktop & Glass Cursor

A phone-and-desktop operating system simulation built around a blur/clear lens, plus a toy cursor trail.

What it is

Two pages share this folder:

  • unblur_page.html (Widget Desktop): a blurred wallpaper that a round "lens" under your pointer reveals in sharp focus. On top of it sit widgets, a Windows-style desktop (desktop screens) or a phone-style home screen (narrow screens).
  • lots_of_square_cursor.html (Glass Cursor): a trail of shapes that follows the pointer, with many styles and a paint mode.

The lens effect

  • Two wallpaper copies are stacked: a blurred one and a sharp one. A clip-path on the sharp one follows the pointer, so only the area under the lens looks sharp. It uses no canvas, so it is cheap on the GPU.
  • Click pins the lens. The wheel changes its size (0.6 to 2.2). On touch devices the lens stays on.
  • The widget board fits the screen by searching for the best CSS zoom value. Widgets only update while visible, and a shared one-second tick sleeps when the tab is hidden.

Desktop and phone modes

  • Desktop (wider than 700px): taskbar, Start menu, draggable windows that snap to the screen edges, right-click new files, and a list of the portfolio projects.
  • Phone (700px or narrower): home pages, an app drawer (swipe up), a notification shade with quick settings (swipe down) and long-press to rearrange.

Glass Cursor

  • A chain of shapes (square, circle, triangle, star, heart, diamond) follows the pointer in 6 palettes and 4 motions (chain, spring, orbit, wave). Sliders and 8 toggles (glow, gravity, paint mode, click bursts, magnet text, sound, autopilot, FPS) change it, with 4 backgrounds.
  • Keys: Space randomise, P paint, C clear, G gravity, H hide panel, F fullscreen.
  • Sharing: your settings are encoded as base64 in the address hash, so copying the URL shares your exact look.
  • Autopilot animates after 2.5 seconds without input. Multi-touch gives one trail per finger.

Reaching this page, and the Help panel

  • The floating "How it works" button is intentionally off on unblur_page.html (data-pos="none" on info-link.js), so the way here is the Help panel, which ends with a link "How this desktop works (full page)".
  • Open Help with ? (also Shift+/), or on the desktop from Start → Tips or the Start button's right-click menu "Tips & shortcuts". Help closes with Esc or by pressing anywhere outside a panel.
  • The Help text has phone-only and desktop-only lines (CSS classes phone-only / desk-only); the KEYS list is desktop only. lots_of_square_cursor.html keeps the floating button (bottom-right, top-left on narrow screens). Both buttons are hidden with ?embed=1 or ?shot=1.

Lens: exact behaviour

ShapeWidth x height (px at scale 1)Corner radius
Bar (default)90 x 2200
Square170 x 1704
Circle190 x 190999 (capped to half the width)
Wide320 x 1108
  • Size = shape x scale, scale 0.6 to 2.2 in steps of 0.1 (rounded). On phones the size is multiplied by a further 0.8.
  • Each frame (requestAnimationFrame, coalesced by queueLens) writes clip-path: inset(top right bottom left round r) on the sharp layer and moves a frame outline with transform: translate. Nothing is repainted on a canvas.
  • The lens does not follow the pointer over UI (selector list UI_SEL: widgets, panels, windows, taskbar, Start menu, context menus, dialogs, drawer, shade, icons). A mouse over UI hides the lens; leaving the window hides it too, unless pinned.
  • While a phone app is open (body.app-open) the lens is hidden (clip-path inset(50%)).
  • Pointer rules: the mouse follows on move. Touch: tapping the wallpaper moves the lens there. On phones touches go through the gesture layer (below): dragging the lens rectangle moves it, tapping bare wallpaper jumps it. A touch-only device wider than 700px (hover: none) starts with the lens on.
  • The mouse wheel over bare wallpaper (not over UI) changes the size by 0.1 per notch.
  • Lens shape, size, wallpaper, accent and grain are saved. Pinning is not saved (resets on reload).

Wallpapers

  • Built in: Portrait, Street, Night. Each is a pair page_images/w_bgN_blur.webp (blurred, always shown) and w_bgN.webp (sharp, shown through the lens). B cycles.
  • "+ Photo" (Settings panel, Settings app or the "Change wallpaper" Start entry) adds one of your pictures through Shell.addWallpaper. Custom wallpapers are saved in wd.customBgs and re-added to the list at load; the chosen index is restored from wd.bg.
  • On the desktop the built-in wallpapers also appear as read-only files in /Pictures/Wallpapers.

Boot order and the module contract

  1. Scripts load in this order: ../04/playlist.js (the track list used by Music), wd/base.js, wd/widgets.js, wd/phone.js, wd/win/icons.js, vfs.js, shell.js, and last wd/app.js. They are plain scripts sharing globals, so order matters.
  2. app.js builds one hidden <section class="widget"> per registry entry, calls init(body) and one tick(now), then restores the board (wd.board) or applies the Default preset.
  3. It then sets accent, grain, lens shape and wallpaper, calls initPhone(), and on a desktop runs Shell.init() and opens the board (wd.deskWidgets, default open). Last it starts the one-second tick.

The widgets board (desktop)

  • Open with W or the taskbar Widgets button, close with its X (title "Hide widgets (W)"). The state is saved in wd.deskWidgets. "+ Add widgets" opens the picker: layout presets plus a tile per widget (on/off, with an "N of 31 on" counter). A widget's own X removes it from the board. Which widgets are on is saved in wd.board as {id: {on: true}}.
  • The board never scrolls. fitBoard first tries zoom 1; if the columns are taller than the free height it does a 9-step bisection between 0.4 and 1 for the largest CSS zoom that fits (the height jumps when a column is added, so a plain ratio would not work). A ResizeObserver and the window resize re-run it.
  • "Reset layout" (Settings panel) re-applies Default and the phone home layout after a confirm; notes, to-dos and other data are kept.

Widget lifecycle

  • Fields: id, name, icon, color, w (default width), big (a larger tile), body() returns the HTML, init(body) runs once at boot, start() / stop() run when it becomes active / inactive, tick(now) runs each second while active.
  • Active means: tab visible, and on desktop board open + widget on + not in zen mode; on a phone, its app is the open one. So a hidden widget does no work. An exception in init or tick is caught and logged, so one broken widget does not stop the rest.

How to add a widget

  1. In wd/widgets.js add def({ id: 'mything', name: 'My thing', icon: '★', color: '#abcdef', w: 260, body: () => '...', init(b) { ... }, tick(now) { ... } }).
  2. Optionally add its id to a preset in PRESETS (app.js), to WIDGET_CAT in shell.js (Start menu category; otherwise "Widgets"), or give it a phone home tile through HW in phone.js. It appears in the picker, Start menu and phone drawer automatically.
  3. Save per-widget data with store.get / store.set (keys become wd.<key>).

Notable widget behaviour

  • Weather and Sun share Geo: location comes from the browser geolocation (10 s timeout, cached up to 1 h) or a city search through the open-meteo geocoding API; it is cached in wd.geo and the weather in wd.wx. Sunrise/sunset, noon and golden hour are computed locally by sunTimes (sun altitude -0.833 deg for sunrise/sunset, +6 deg for golden hour; null in polar day/night).
  • Music is one shared <audio> used by the widget, the phone media notification, the quick tile and Explorer's Music folder. Space toggles it. Saved: wd.track, wd.vol.
  • Ambience offers Rain, Wind, Waves, Fire and Café. Piano and Metronome save pianoWave, bpm and beats.
  • Games save best scores (snakeHi, wpmBest, ttt, tttHard).

Phone mode in detail

  • Gesture layer (onDrag): the home screen, drawer and shade use touch-action: none; a swipe locks to an axis after 9 px of movement and tracks velocity (reset if the finger rests more than 90 ms). A click right after a gesture is swallowed for 120 ms.
  • Home: items are packed into a 4-column grid, cell 88 px, gap 8 px; rows = 3 to 7 depending on the free height. A page break item | separates pages. The default home has three pages (clock, music, weather, calendar, photos and to-do; then weather, calendar, to-do, countdown and moon tiles; then search, photos and quote). The dock holds Music, Notes, Timer and Apps. Saved in wd.homeItems; invalid ids are dropped on load.
  • Page swipe: moves to the next/previous page if you drag more than 22% of the screen width or flick faster than 0.35 px/ms.
  • Pull down (from the status bar or a downward swipe) opens the notification shade; it commits if dragged past 35% of the sheet or flicked down faster than 0.4. Swipe up opens the app drawer (commits past 30% of 0.55 screen heights or a flick faster than 0.4); from the open drawer a drag down of more than 60 px or a quick flick closes it.
  • Long-press an item on a home page for 480 ms (with a short vibration if supported) to enter edit mode and drag it (holding near a page edge flips the page after 700 ms). The minus button removes, "+ Widgets" opens the picker, Done or tapping empty space exits. Long-press an app in the drawer for 520 ms to add it to Home.
  • Layers: app, drawer and shade each push a browser history entry, so the system Back gesture or Esc closes the top one. Widgets have a back arrow that calls history.back().
  • Quick settings tiles: Lens, Pin lens, Shape, Wallpaper, Music, Film grain, Do not disturb, Location. A brightness slider (0.35 to 1) dims the wallpaper (wd.dim).
  • Notifications: three seeded ones (Welcome, a project promo, a message), plus a random one every 30 to 75 s on a phone (60 to 150 s on desktop), only while the tab is visible and not turned off in Settings (nfRandom); Do not disturb switches pop-ups off. Cards swipe away left or right (past 35% of their width or a flick faster than 0.5); heads-up banners hide after 5 s or a swipe up. Playing music adds a media notification.
  • Special apps: Settings and Wallpaper open the settings panel, Portfolio leaves to the main page, Apps opens the drawer.
  • Resizing across the 700 px line rebuilds the mode live (phone layers dropped; Shell.init() when going to desktop).

Desktop shell in detail

Windows

  • Apps load on demand: Shell.launch(id) injects wd/win/apps/<id>.js the first time, which must register WinApps.<id> = { mount(win, args) ... }. A failed load shows a toast "Couldn't open ...". Some apps are single (one window: Calculator, Clock, Settings, Solitaire) and some reuse an existing window (Browser, Photos).
  • Default sizes (w x h): Explorer 880x560, Browser 1040x660, Notepad 740x500, Paint 1000x660, Photos 860x580, Calculator 340x560, Clock 700x520, Settings 940x640, Solitaire 940x680. The minimum size is 320 x 220 unless an app sets minW / minH. Windows resize from edges and corners and stay above the 48 px taskbar; positions persist in wd.winBounds.
  • Snap: dragging a title bar until the pointer is within 3 px of the top edge maximises; within 3 px of the left or 4 px of the right edge fills that half (a preview shows first). Pulling a maximised or snapped window away restores it under the cursor. Alt+F4 closes the focused window.
  • Alarms and timers (Shell.clock) keep running when the Clock app is closed and ring with a chime. The default alarm is 07:30 "Wake up", weekdays, off.

Taskbar, Start, desktop

  • Start has pinned items (default pins: Browser, Explorer, Notepad, Paint, Photos, Calculator, Clock, Settings, Solitaire, Widgets, Wallpaper, a few projects, Music, Weather and Tips), an all-items list with search over names and keywords, recent files and a power menu: Sleep (full-screen sleep screen, any key or click wakes), Restart (reloads), Shut down (back to the portfolio page). Right-click items to pin/unpin; taskbar alignment and pins are saved.
  • The launcher can start apps, "Widgets", "Change wallpaper", "Tips" (Help), every portfolio project (opens its URL) and every widget (w:<id>, opened as a window).
  • Right-click the empty desktop for new files and folders; files from your computer can be dropped on it. Desktop icons open with Enter. Esc closes, in order: context menu, Start, flyouts, the widget picker.
  • Inside apps: Browser Ctrl+L or F6 address bar, Alt+Left / Right back / forward, F5 reload. Notepad Ctrl+O / S / F / A, Ctrl+Shift+S save as, zoom Ctrl+= / - / 0. Paint Ctrl+Z / Y. Explorer Ctrl+A and Ctrl-click multi-select.

Virtual file system (wd/win/vfs.js)

  • Roots: Desktop, Documents, Downloads, Music, Pictures, Recycle Bin. /Pictures/Wallpapers, /Pictures/Projects and the root are read-only and built from code: wallpapers, project screenshots (with a link to the project) and the music library (/Music/Title - Artist.mp3).
  • Your files are records {path, name, type, mime, size, ...} saved in IndexedDB. Text types: txt md log csv json html css js xml ini; image types: png jpg jpeg webp gif bmp svg. Illegal characters \ / : * ? " < > | are stripped from names. Changes fire an fs event on document so open Explorer windows refresh.
  • A welcome file /Documents/Welcome.txt is offered in the Start "recent" list on first run; the seed flag is fsSeeded.

How to add a desktop app

  1. Create wd/win/apps/myapp.js with WinApps.myapp = { mount(w, args) { w.body.innerHTML = ...; } } (see notepad.js for a full example).
  2. Add an entry to APPS in shell.js: { id, name, icon, cat, w, h, minW, minH, single, reuse, kw }; optionally add it to DEFAULT_PINS.
  3. If the site is used offline, regenerate the offline file list (tools/build_offline_manifest.py) so the new file is cached.

  • Panel buttons: Randomize, Copy link, Clear paint, Save PNG, Fullscreen, Reset. The panel collapses with the arrow and starts collapsed at 640 px or narrower.
  • Persistence order: defaults, then localStorage["glass-cursor"], then the URL hash (the hash wins). "Copy link" writes # + btoa(encodeURIComponent(JSON)) of all settings to the address bar and the clipboard (if the clipboard is blocked the link stays in the address bar). A bad hash is ignored.
  • Trail model: each pointer has 60 segments (only Length are used) and a position history of up to 120 points. Chain: segment i aims at the history point 1.6 x i steps back. Spring: each segment follows the one in front. Orbit: segments circle the pointer on radius 18 + 3.2 x i. Wave: like chain, but the pieces rotate. Size shrinks along the trail to 45% (orbit also halves it).
  • Gravity: segments gain downward velocity (capped at 12) in proportion to their position along the trail, and burst bits fall faster (0.35 vs 0.12 per frame).
  • Click bursts: 26 bits (8 with reduced motion), speed 2 to 8, fading at 0.018 per frame, at most 400 live bits.
  • Paint mode: the head of each live trail stamps a piece (35% of Size, 60% alpha) on a second canvas that never clears by itself; Clear paint, Reset and the C key wipe it. The paint canvas is kept on resize. Save PNG merges the background colour, paint and trail at device resolution into glass-cursor.png.
  • Magnet text: the title letters move away from the pointer within 160 px (up to 40 px shift); letter positions are re-measured after fonts load.
  • Sound (off by default) plays soft Web Audio blips whose pitch follows pointer speed; click bursts add a blip.
  • Autopilot: after 2500 ms without input (and no live trail) a Lissajous path around the screen centre (about 32% of the width) is drawn as a trail named "auto". Any input removes it.
  • Pointers: one trail per pointer id. Mouse trails are permanent; touch trails exist only while the finger is down and fade after release. Fast strokes use coalesced events. The OS cursor is hidden over the canvas but returns over the panel, and presses on the panel do not draw.
  • Performance: canvas scale is capped at 2x device pixels; the loop sleeps after about 20 still frames and input wakes it, so an idle page costs nothing (autopilot keeps it awake). prefers-reduced-motion makes follow tight (0.6) and bursts smaller. The FPS toggle shows fps, trail count and bit count.
  • Keys are ignored while a slider or select has focus. H hides the whole panel (press again to restore).

How it differs from the other projects

A whole interface family (phone and desktop) driven by one small lens trick. It is modular: each widget or app is a separate file, so adding one is easy.

Main quality

The signature blur-to-clear lens, with an unusually large set of widgets and apps behind it.
