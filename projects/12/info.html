How it works · Project 12

Computer A-83

A 3D 1980s computer on a poster, with a working terminal and clickable keys.

What it is

A poster with a red circle, black half-ring, red square, "A-83", katakana and the word COMPUTER, and a 3D retro computer in front. Spin and zoom it, tap the screen to power it on, then tap its 3D keys or use your own keyboard to type into a green terminal.

Controls

  • Drag sideways to spin (0.45° per pixel, with a flick). After 6 seconds idle it eases back to the poster angle by the shortest way. A touch moving less than 6 px counts as a tap, not a drag.
  • Zoom: mouse wheel over the model, two-finger pinch, or the + and − buttons (0.7× to 4.5×). In the embedded main-page panel an idle zoom eases back to 1× after 6 seconds; on the standalone page it stays. ↻ resets.
  • Controls (full page only, hidden inside the main-page panel): a "Cavity: on" label (not a button: the filter is always on, only ?cav=0 turns it off), the Numbers button, zoom − / + and reset. The keycap labels have no button: they switch on by themselves when you tap the screen to power on, and stay on.
  • Power: tap the screen to start the terminal. Keys do nothing until then (and in the main-page panel the terminal stays off).
  • Keys: tap any of the 40 3D keys. It travels down about 3.5 mm, glows orange and types. Real keyboard letters, Enter, Backspace, Esc, Space and Shift also move the matching 3D key.
  • Number layer: tap the 3D CTRL key, press Alt, or tap the Numbers button (for phones). The screen boot text and the bottom hint also remind you that the Alt key switches numbers and letters. The top row becomes 1-0, other keys become symbols, key labels turn orange and the screen shows NUM.
  • Up / Down walk through terminal history. Left / Right spin the model 15°.

URL options for tuning: yaw, elev, fov, cx, cy, h place the computer on the poster. zoom, cav=0 (cavity filter off), cavr, ridge, valley, labels=1, debug=1, embed=1, shot=1.

How it works

  • Screen: an emissive canvas texture drawn by the terminal code. A click is ray-cast against the model; for the screen the hit coordinate is mapped back to canvas pixels.
  • Keys: each key is its own mesh. Keys are labelled QWERTY by their row position (rows are found from the model's depth coordinate). A real key press is mirrored on the 3D key.
  • Shading: normals are rebuilt on load with a 35° crease angle so box edges stay sharp while curves stay smooth.
  • Cavity filter: the scene is drawn to one buffer in colour and to a second buffer as surface directions. A shader compares neighbouring directions to find ridges (lightened) and creases (darkened), like a Blender cavity pass.
  • Placement: the camera distance is solved iteratively so the computer's silhouette lands on a target rectangle of the poster.
  • Efficiency: it renders only when something changes, pauses when hidden or off-screen, and the terminal cursor stops blinking after 20 seconds without a touch.

Embedding

Inside the main page

  • The main page shows this poster in a panel under the BMW card using ?embed=1. That hides the HOME and How it works buttons and keeps vertical swipes free so the main page can still scroll.
  • On phones the panel first shows a screenshot with a pulsing TAP TO PLAY. The real page loads only after a tap, and its files are prefetched when the phone is idle (skipped on data saver or 2G).
  • ?shot=1 hides hints and buttons, for taking clean thumbnails.
  • The page stops its render loop when the tab is hidden or the panel is scrolled out of view.

Changing it

  • New terminal command: add a case in the command function (run) in index.html and add it to the help text.
  • New model: replace old_computer.glb; the screen and key node names above are what the code looks for.

Gestures and rules in detail

  • Spin speed: a drag turns the model by 0.45 / poster scale / sqrt(zoom) degrees per pixel, so it feels the same on any screen size and slows down when zoomed in. Release with speed and it coasts (speed x 0.92 per frame, stopping below 0.01). Turning is always about the vertical axis.
  • Tap versus drag: a press moves less than 6 px in total (x plus y) is a tap. A tap on a key types it (the key is pressed for 160 ms); a tap on the screen powers it on (term.start()). A press on a key also pushes it down for 120 ms at once, before you know whether it is a tap.
  • Where a drag can start: only on the computer's area (a box 600 wide by 1.12 x the target height around the target centre). When zoomed in beyond 1.15x the whole poster is the touch area. Outside it a touch scrolls the page as normal; the mouse wheel only zooms when the pointer is over the model itself.
  • Pinch: a second finger cancels the drag and scales the zoom by the finger distance ratio. + and - buttons multiply or divide the zoom by 1.35; the reset button restores zoom 1, the resting angle and stops any coasting. Zoom animates (25% of the gap per frame).
  • Return home: after 6 s without input the model slerps back to the resting angle (5% of the remaining rotation per frame, by the shortest way).
  • Zoom auto-return only applies in the embedded panel (?embed=1): there an idle zoom eases back to 1x after 6 s. On the standalone page a zoom stays until you change it.
  • Picking uses a ray from the pointer against the model, so keys hidden behind other parts are not hit. The cursor becomes a pointer over keys and the screen, and a grab hand over the computer.
  • Key travel: a pressed key moves down 0.0035 model units and its emissive glow (orange, 0xff7a30, up to 0.9) eases in and out (45% per frame).

The 40 keys and the number layer

Rows are found from the key meshes' depth position (rounded to 0.008) and sorted left to right, then named from this layout (back row first):

  • If a row has a different number of keys than listed, the console warns and extra keys are labelled "?".
  • On-screen Shift (3D key tap): the next tapped letter is typed upper case, then Shift resets.
  • Number layer (tap CTRL or press Alt) maps 3D key taps: Q-P to 1 2 3 4 5 6 7 8 9 0; A S D F G H J K L to + * / ( ) . % ^ ?; ; to :; ' to ". Z X C V B N M to ! @ # $ & _ =; , . / to < > \. Labels on the keycaps are redrawn orange while the layer is on and the screen footer shows NUM. The real keyboard always types its own characters, regardless of the layer.
  • Key labels are small decals on every key top (they never intercept taps). They turn on when the screen is tapped to power on and have no off button. In the main-page panel the screen stays off, so they stay hidden.

Terminal internals

  • Screen: a 640 px wide canvas whose height follows the screen mesh's aspect; text is 28 px bold Courier New, 34 px line height, margins 62 / 44. Columns = floor((width - 124) / (28 x 0.6)) (about 33-34); rows = what fits above the footer. Output lines wrap at the column count and the oldest scroll off.
  • Look: glowing text (shadow blur 9), scanlines every 3 px at 22% black, a radial vignette, and a footer showing "KEY: last-key" on the left and the colour name (with NUM when the layer is on) on the right. The canvas is used as the emissive map (intensity 1.1) of a dark glass material. The screen mesh gets planar UVs computed from its bounding box.
  • Power: before the first tap the screen is dark glass with a faint reflection. The first tap runs a boot sequence (A-83 PERSONAL COMPUTER, BASIC V1.0, 48K BYTES FREE, TYPE HELP), one line per 140 ms; input is blocked during boot. reboot replays it. In the embedded panel the screen never turns on.
  • Input line: shown as > text with a blinking block cursor (toggles every 530 ms; stops redrawing after 20 s without touch to save power). Maximum length is columns minus 3. Enter echoes the line, then runs it.
  • Parsing: the line is trimmed and split on whitespace; the first word (case-insensitive) is the command and the rest is its argument. Unknown commands print ?SYNTAX ERROR. A non-empty line is added to history (30 entries max).
  • Command details: help takes a page 1 to 3; color takes green, amber, white or cyan, and with no or an unknown argument cycles to the next colour; rand N gives 1..N (default 100); roll N gives a die with N sides (minimum 2, default 6); banner TEXT draws a star box; history lists the last 8; mem shows a fake free-memory figure that goes down as you type more commands (down to 8K free); uptime counts from page load; cat / type read from a small in-code file table (README.TXT, NUMBERS.TXT, JOKES.TXT, SECRET.TXT) and ls / dir lists it.
  • calc accepts only digits and + - * / ( ) . % ^ and spaces (checked with a regular expression), turns ^ into **, evaluates with a strict-mode Function, and prints the result to 12 significant digits. A bad expression gives ?BAD EXPRESSION, a syntax problem ?SYNTAX ERROR, a non-finite result ?MATH ERROR.
  • guess starts a mode: the computer picks 1 to 100; every line is then a guess (HIGHER / LOWER / YES with the try count). Type quit or q to stop; any other command is not available until the game ends.
  • Display state (colour, history, NUM layer) lives in memory only; nothing is saved between visits.

Rendering details

  • Poster: an 800 x 1200 unit stage scaled to fit the window; the 3D canvas has the same size and its pixel ratio is min(2.5, devicePixelRatio x scale).
  • Lights: hemisphere (white / 0xcfc8b8, 1.5), a sun (2.4) casting a 2048 px soft shadow onto an invisible shadow-only floor (20% opacity), and a cool fill (0.5). The floor is hidden whenever the model is tilted away from upright.
  • Model prep: only the HEAD node is used; every mesh gets creased normals (35 degrees), casts and receives shadows, and textured materials are cooled slightly (colour 0.86, 0.9, 0.96). The model is then centred on x and z and sat on y = 0. Keys get their own cloned material so each glows separately.
  • Placement solver: at the resting angle the silhouette bounds of sampled vertices (about 400 per mesh) are projected, and the camera distance is multiplied by (current height / target height) six times; a view offset then shifts the centre to cx, cy. It runs again on load.
  • Cavity pass: colour goes to a 4x multisampled half-float target; a second pass draws view-space normals (without the floor); a full-screen shader measures how fast the normal changes at radius r (mixed 65% r and 35% 3r). Convex gives a brighter pixel (x ridge), concave a darker one (x valley), clamped to 0.35 to 1.5. The result is composited with premultiplied alpha. cav=0 skips it (there is no button for it) and renders directly.
  • Grain: a 256 px noise tile jumped to a random offset every 90 ms (static with reduced motion).
  • Efficiency: nothing renders unless a dirty flag is set (input, easing, key motion, terminal repaint). The loop stops completely when the tab is hidden or the stage is off screen and resumes on wake. The terminal only repaints on change.

How to customise

  • Add a command: in the terminal block of index.html add a case 'name': print('TEXT'); break; in run() (output is upper case by convention), and add it to the right HELP page (three strings, about 3 lines each). Add files to the FILES table to make them show up in ls / cat; extend JOKES and FORTUNES arrays the same way.
  • Add a colour: add an entry to COLORS (it is then accepted by color and used in the cycle).
  • Change the number layer: edit the NUM table.
  • Move or retune the computer: use the URL options above to find values, then change the defaults in the num('yaw', -26) style lines at the top of the script.
  • Change the keyboard layout: edit LAYOUT; counts must match the model's key rows (40 keys).
  • Look and feel: DEG_PER_PX, RETURN_AFTER, STEP, TAP_PX, ZMIN / ZMAX; the CAV defaults; the terminal's FS, LH, PX, PY for text size and margins.

How it differs from the other projects

Opposite of the Fuji Poster (10): the poster is flat art and the 3D model is the main thing, with its own tiny operating system in the terminal.

Main quality

A tactile 3D computer: physical keys you can press, a live terminal and a Blender-style cavity shader, all on a poster.
