How it works · Project 02

Just Jump It

A Unity 3D platformer exported to WebGL.

What it is

A 3D jump platformer made in Unity and exported to WebGL. The page around it only loads the game and makes it behave on phones.

Files and loading

FileRole
index.htmlLoads the Unity loader, shows a progress bar, handles fullscreen and mobile layout.
Build/justjumpit_build.loader.jsUnity's loader script.
Build/*.unitywebCompressed game data, framework and WebAssembly.
TemplateData/style.cssUnity's standard template style.
  • The page injects the loader and calls createUnityInstance, updating a progress bar while it downloads.
  • All build files are in the offline "heavy" list.
  • The Unity instance is kept in window.unityInstance, which a CLOSE GAME button inside the game uses.

Controls and page behaviour

  • A fullscreen button calls unityInstance.SetFullscreen(1). The game's own controls are defined inside the Unity project.
  • Desktop: the canvas is a fixed 960×600.
  • Phone: the page detects mobile and adds a class that stops scrolling, overscroll and pinch, sets the pixel ratio to 1 for speed, and fills the screen. The first tap requests fullscreen and tries to lock landscape. In portrait an overlay says "Rotate your phone to landscape to play".

  • The .unityweb files are pre-compressed by Unity, so the server must serve them with the right Content-Encoding, or the page cannot decode them.
  • unityShowBanner(msg, type): an error banner is red and stays; a warning banner is yellow and, like other messages, is removed after 5 seconds (5000 ms).
  • If createUnityInstance fails, the error is shown with alert().
  • The loading bar element is shown before the loader script is added, and hidden once the instance exists. The bar width is 100 * progress percent.

Mobile handling in detail

  1. A phone is detected with the user-agent test /iPhone|iPad|iPod|Android/i.
  2. A second viewport meta is added: width=device-width, height=device-height, initial-scale=1.0, user-scalable=no, shrink-to-fit=yes.
  3. The container and canvas get the class unity-mobile (Unity's full-window style), the canvas gets touch-action: none, and html gets jji-mobile, which removes margins, hides overflow, sets overscroll-behavior: none and a black background.
  4. config.devicePixelRatio = 1: the game renders at CSS resolution instead of 2x to 3x on high-density screens, which is much cheaper on the GPU at the cost of some sharpness.
  5. A one-time touchend listener requests fullscreen (requestFullscreen or the webkit version) on the whole document, then tries screen.orientation.lock('landscape'). Failures are swallowed. It works on Android Chrome; iPhone ignores the lock. The listener removes itself after the first tap.
  6. The rotate overlay #jji-rotate (dark teal, 22px bold text) is shown only when the (orientation: portrait) media query matches and the page is in mobile mode, so in landscape it is hidden.

On desktop the canvas is set to 960px by 600px, with the HTML attributes width=960 height=600 as well. The footer holds the WebGL logo, the fullscreen icon and the title "Just Jump It".

Limits and changing it

  • No localStorage, URL options or keyboard shortcuts exist in the page; the fullscreen icon is the only page-level control. Game input and saves live inside the Unity build.
  • The Unity source is not in this repository. To change the game, rebuild in Unity for WebGL with the product name that produces justjumpit_build.*, copy the Build/ files over, and keep the file names or update the four URLs above.
  • To tune mobile speed, change config.devicePixelRatio (1 now); to change the desktop size edit the 960 by 600 values.
  • window.unityInstance is set only after loading finishes, so anything that calls it earlier (such as a CLOSE GAME button) should check that it exists.

How it differs from the other projects

A second full engine (Unity), compiled to WebAssembly. Unlike the Three.js projects the game logic is not in this repository as readable code, only the exported build is.

Main quality

A complete Unity game running in the browser, with mobile fullscreen and landscape handling and a reduced pixel ratio to keep it smooth.
