How it works · Project 11

Cut-Out Studio

AI background removal that runs on your own device.

What it is

Pick a photo, press a button and the background disappears. Then swap in a colour, a gradient, a blur of the original or your own picture, compare before and after with a slider, and download a PNG. The photo never leaves your browser.

Tools used

  • Transformers.js 3.0.2, loaded from the jsDelivr CDN, runs the model in the page.
  • RMBG-1.4 (briaai), about 45 MB, a background-removal model. Its license is non-commercial.
  • WebGPU is used when the browser has it, with a WebAssembly fallback. A canvas does all compositing.

How it loads

  • Nothing heavy loads at first. The library and the model download only when you press Load AI model, with a progress bar. If WebGPU fails it retries on WebAssembly.
  • The CDN files are cross-origin, so the offline cache does not store them. This tool needs a connection the first time (the browser keeps its own model cache afterwards).

Controls

  • Choose image, drag a file anywhere on the window, or Try a sample.
  • Remove background runs the model. Download PNG saves cutout.png.
  • Background swatches: transparent (checkerboard), white, black, red, cream, gradient, blurred original, a custom colour, or Image… to upload a backdrop.
  • Drag the divider to compare before and after (works once a cutout exists).

How it works

  1. Photos wider than 2000 px are shrunk first.
  2. The picture is turned into model input: 1024×1024 pixels, normalised.
  3. The model returns a mask (how likely each pixel is foreground), scaled to 0-255.
  4. The mask is resized to the photo's size and written into the alpha channel of the original photo.
  5. The chosen background is drawn first, then the cut-out on top.

Model and preprocessing details

  • Library: import() of @huggingface/transformers@3.0.2 from jsDelivr, done only when you press the load button. env.allowLocalModels is false, so weights come from the Hugging Face hub (briaai/RMBG-1.4) and are kept in the browser's own cache.
  • Device: WebGPU if 'gpu' in navigator, otherwise WASM. If the WebGPU load throws, it retries once on WASM. The status line says "Model ready (WebGPU)." or "Model ready (CPU, slower).". If WASM also fails, the error is shown in red and the button is re-enabled so you can retry.
  • Progress bar: sums loaded and total over all files reported by the progress callback and shows "Downloading model... X / Y MB".
  • Processor config (set in code): resize to 1024×1024, no padding, rescale by 1/255, mean 0.5 and std 1 on every channel, resample 2 (bilinear). That maps pixels to the range -0.5 to 0.5.
  • Inference: RawImage.fromURL(before.src), processor(image), model({input}). The first output is multiplied by 255, cast to uint8 and resized to the photo size.
  • Mask post-processing: there is none. The 0-255 value is written straight into each pixel's alpha, so soft edges come from the model's own confidence (no threshold, feathering or erosion).
  • Large photos: the longer side is limited to 2000 px (MAX) by redrawing on a canvas and re-encoding as PNG. Smaller photos are used as they are. The status line shows "Done in N s." after a run.

Compositing, compare slider and download

  • Background modes (bg): none (transparent, the checkerboard shows through), a CSS colour (white #ffffff, black #111111, red #ff5a47, cream #f1e8d6, or the colour picker, default #4a6fa5), grad, blur, image.
  • Gradient: a diagonal linear gradient #ff9966, #ff5e62 (middle), #6a5acd. Blur: the original drawn 20 px oversize on each side with ctx.filter = blur(max(8, width/70) px), so the blur scales with the photo and edges do not fade. Custom image: scaled to cover and centred (cropped, not stretched).
  • Changing a swatch only redraws the canvas (render()); the model is not run again. The cutout canvas stays at the photo's resolution.
  • Compare slider: the original <img> sits over the result canvas and is clipped with clip-path: inset(0 X% 0 0). Pointer events with pointer capture move the divider (0 to 1 across the view), so mouse, touch and pen all work. It is only active once a cutout exists (the view gets the cut class, which also shows the Before/After tags); before that the original fills the view. The view's touch action is pan-y, so vertical page scrolling still works on phones.
  • Download: out.toBlob(image/png) of the canvas as it looks (cutout plus chosen background), saved as cutout.png; the object URL is revoked after 2 s. The button is disabled until a cutout exists.
  • The view's width is min(100%, 70vh × aspect ratio), so tall photos never exceed 70% of the screen height.

Inputs, state and failure modes

Input / stateBehaviour
Choose imageaccept="image/*", first file only; the input is reset so the same file can be chosen again.
Drag and dropListens on the whole window; the drop card highlights while dragging; only files whose type starts with image/ are accepted.
Try a sampleLoads ../03/images/f1_pitstop.jpg (an image from project 03).
Run buttonDisabled until both a model and a photo exist; reads "Load the model first" until the model is loaded. Loading a new photo clears the previous cutout and disables Download.
StorageNothing in localStorage, no URL options. Photos stay in memory as object URLs.
  • Unreadable image: status "Could not read that image." (red). Inference error: "Something went wrong: ..." with the message, and the buttons are restored.
  • No connection on first use: the library import or model download fails and the error is shown. The CDN is cross-origin, so the service worker does not store it.
  • Only one photo is held at a time, and inference runs on the main thread, so the page can freeze briefly on slow CPU (WASM) runs.

How it differs from the other projects

The only project that runs a machine-learning model, and the only one that depends on an outside CDN at runtime.

Main quality

Private, on-device AI cut-outs with a live before/after slider and many backgrounds.
