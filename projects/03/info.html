How it works · Project 03

Image Effects Studio

Scanline, ASCII and pixel-art effects, live in the browser.

What it is

Load a picture (or use the sample) and see it as the original plus three retro effects at once in a 2×2 grid. Sliders change each effect live and each result can be downloaded as a PNG.

Files and loading

  • One page, plain JavaScript and canvas. No libraries.
  • The default picture is images/f1_pitstop.jpg, also kept in the offline cache.

Controls

  • Choose a file, or drag and drop an image onto the Original section.
  • Sliders: scanline density (1-10), ASCII scale (20-200), pixel block size (1-20), number of colours (4-40).
  • A Download button under each effect saves it as a PNG.
  • Resizing the window redraws everything.

How each effect works

EffectLogic
ScanlinedrawScanline blacks out every Nth row of pixels.
Pixel artdrawPixelArt averages blocks of pixels, then snaps each block to a small palette taken evenly from the picture's own colours.
ASCIIdrawASCII shrinks the picture to a tiny canvas and maps each pixel's brightness to a character from .:-=+*#%@ (darkest is a space), drawn in 6px monospace.

Page layout and state

  • A 2×2 CSS grid (.container) below the 60px site bar, 10px gap and padding. html, body are overflow:hidden, so the page never scrolls; each cell is one quarter of the window.
  • Each effect canvas is created off-screen at the exact pixel size of its cell (clientWidth x clientHeight), converted with toDataURL() and set as the cell's CSS background-image (cover, centred). The Original cell simply shows the image as a CSS background.
  • The last canvas of each effect is kept in the canvases object (scanline, ascii, pixel) for the download buttons. Nothing is saved to localStorage; reloading restores the default picture and default slider values.
  • Every effect first draws the picture with a cover fit: scale = max(w/img.width, h/img.height), centred, so the picture fills the cell and the overflow is cropped.

  • Sliders use the input event, so effects update continuously while dragging.
  • Loading: the hidden <input type=file accept="image/*"> is triggered by the Click to select label; dropping a file on the Original cell takes only the first file and only if its MIME type starts with image/. The file is read with FileReader.readAsDataURL and assigned to img.src.
  • While a file is dragged over the Original cell its background turns #333; on dragleave it is set to #252525 (this replaces the shorthand background, so the picture may disappear until the next load).
  • Download buttons save scanline.png, ascii.png and pixel.png at the on-screen cell size (not the original resolution). The ASCII PNG has a transparent background with grey text.

Algorithm details and constants

Scanline

Loop over rows y; when y % density === 0 the R, G and B bytes of the whole row are set to 0 (alpha stays 255). Density 1 therefore blacks out every row; density 10 blacks out one row in ten.

Pixel art

  1. All pixels of the cropped canvas are read into an array of [r,g,b].
  2. The palette is built by sampling that array every step = floor(pixelCount / numColors) pixels until numColors entries exist. It is a plain even sampling in scan order, not a clustering algorithm like k-means, so the palette mostly contains colours from the upper part of the picture and the same colour can appear several times.
  3. The canvas is walked in blocks of blockSize; the block's average (Math.floor per channel, edge blocks only count pixels inside the canvas) is replaced by the nearest palette entry using squared RGB distance, and the whole block is filled with it.
  4. Cost is roughly (pixels) + (blocks x palette size), which is why block size 1 with 40 colours is the slowest setting.

ASCII

  • The picture is drawn (cover fit) into a tiny temporary canvas of scale x floor(scale*0.6) pixels, where scale is the slider value. The 0.6 factor compensates for characters being taller than they are wide.
  • Each tiny pixel gives brightness avg = (r+g+b)/3; the character is chars[floor(avg/255 * (chars.length-1))] with chars = " .:-=+*#%@" (starting with a space for the darkest tone).
  • Characters are drawn with fillText in 6px monospace, colour #aaa, at x = column x (cell width / columns) and y = row x (cell height / rows). A larger slider means more, denser characters; a small one gives a coarse, large-spaced result.

Edge cases

  • The default image is drawn when img.complete is true at script time; otherwise img.onload is set to redraw. Because that handler exists only in the second case, an uploaded file redraws the effects automatically only if the default image had not been cached when the script ran; in the other case move any slider or resize the window to refresh the effects.
  • All processing is synchronous on the main thread, so very large photos or huge windows can make slider dragging feel heavy.
  • The page is touch friendly through the native range inputs; there is no keyboard shortcut of its own.

Customising

  • Default picture: change the path in img.src = "./images/f1_pitstop.jpg" (and keep it in the offline manifest).
  • Slider ranges and defaults: the min, max and value attributes on the four input type=range elements.
  • ASCII look: the chars string (dark to light), the 0.6 aspect factor, the font string and fillStyle in drawASCII.
  • Add an effect: add a .section block in the HTML, write a drawX function that ends with setSectionBackground(canvas, section, key), call it in processDefaultImage and the resize handler, and add a download button calling downloadCanvas.

How it differs from the other projects

The simplest one technically: pure canvas pixel processing with no 3D, no network and no framework.

Main quality

Four-way live comparison: you see the original and three effects side by side while you drag the sliders.
