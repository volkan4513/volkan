How it works · Project 03

Retro Image Effects Studio

Scanline, CRT, ASCII, pixel-art and halftone effects, live in the browser.

What it is

Load a picture (upload, drop, paste, a sample, or the webcam) and see it as the original plus three retro effects at once. Each of the three effect panels can show any of five effects. Sliders change the effect live, and each result can be downloaded as a PNG at the picture's own resolution.

Files and loading

  • One page (index.html), plain JavaScript and canvas. No libraries.
  • The default picture is images/f1_pitstop.jpg, also kept in the offline cache.
  • Sample pictures in the top bar: the default, ../10/shot.webp (Fuji poster), ../12/shot.webp (Computer A-83) and a "Sunset grid" drawn in code by makeSunset() (needs no file). A sample whose file fails to load hides its own button.
  • The page must be served over http(s). Opened straight from disk (file://) the browser blocks reading canvas pixels, so the pixel-reading effects fail.

Controls

  • Picture: the Upload button, a click anywhere on the Original picture, drag and drop anywhere on the page (the Original panel gets a dashed outline), or paste an image from the clipboard. Only the first file is used and it must be an image.
  • Samples: the four small thumbnails in the top bar. The chosen one has a yellow border.
  • Webcam: starts the camera and all four panels update live (about 12 times a second). Stop cam keeps the last frame as a still picture to keep editing. The button is hidden when the browser has no camera API; the camera needs https or localhost.
  • Effect list in each panel header: Scanline, CRT, ASCII, Pixel Art, Halftone. Each panel remembers its settings per effect.
  • Download saves that panel as a PNG. Copy text (ASCII only) copies the characters to the clipboard. Share (only shown where the browser can share image files, mostly phones) sends the PNG to the system share sheet.
  • Compare checkbox in each effect panel: shows the original on the left and the effect on the right of a divider. Drag anywhere across the picture to move the divider. Downloads are not affected.
  • Fit (top bar): fill (crop) crops the picture to fill each panel; whole image shows all of it with empty bars at the sides or top, and downloads are then the full uncropped picture.
  • Save all saves one PNG, retro-effects.png, with the original and the three effects in a 2×2 sheet.
  • Copy link copies an address that opens the page with the same effects and settings (see Saved settings and links).
  • Expand (or a double-click on an effect picture) shows one panel over the whole page; Close or Esc goes back.
  • Reset puts every panel back to its default effect and default slider values and switches Compare off. The picture and the Fit mode stay.

The five effects

ScanlineLine spacing 2-12 (3), Darkness 20-100% (90)Draws the picture, then a dark stripe every spacing pixels. Stripe thickness is a third of the spacing (at least 1 pixel).
CRTCurvature 0-40 (14), Glow 0-100% (45), Line spacing 2-8 (3)Bends the picture like a tube screen, adds scanlines, a red/green/blue stripe mask and darker corners, then adds a blurred copy on top for glow.

Default panels: Scanline (top right), ASCII (bottom left), Pixel Art (bottom right).

Page layout

  • Top bar (.bar): a 100px gap for the fixed HOME button, the title (hidden under 1180px wide), sample thumbnails, Upload, Webcam, Reset, Fit, Save all, Copy link, and the INFO button, which info-link.js puts inside the bar (data-slot=".bar"). The bar wraps onto more rows on narrow screens.
  • An effect with four controls (Pixel Art) lays them out as a 2×2 grid (.ctls[data-n="4"]); the others sit in one row.
  • Desktop: a 2×2 CSS grid that fills the rest of the window; the page does not scroll.
  • Phones (700px wide or less): one column that scrolls; each picture is 62% of the screen width tall (at least 200px). Short windows (520px tall or less), such as a phone on its side: two columns that scroll, pictures 70% of the window height.
  • Each panel is a column: header row, picture, then the controls below the picture, so nothing covers the image.
  • Every slider shows its current value in yellow next to it. The Colours slider is greyed out unless the palette is "From image".

How drawing works

  • Each panel has a real <canvas> on the page. Effects draw straight into it; there is no toDataURL() step while you drag a slider.
  • The canvas is sized to the panel in device pixels: CSS size × devicePixelRatio, capped at MAX_DPR = 2. In webcam mode the factor is 1 to keep it fast.
  • schedule(panel) queues one redraw per animation frame, so many slider events in one frame cost a single draw. Only the panel you changed is redrawn.
  • A ResizeObserver on each picture redraws that panel RESIZE_DELAY = 90 ms after the last size change (debounced).
  • Every effect starts with a cover fit (drawCover): scale = max(w / imageWidth, h / imageHeight), centred, so the picture fills the panel and the overflow is cropped.
  • Effect functions have the form draw(ctx, W, H, s, o, panel): W×H in canvas pixels, s = canvas pixels per CSS pixel, o = the settings. All sizes are multiplied by s, so an effect looks the same on screen and in a large download.
  • Download draws the effect again on an off-screen canvas with the same crop as the preview but at the picture's own resolution: s = max(1 / coverScale, screen factor), with the longest side capped at MAX_EXPORT = 4096. It is saved with toBlob as scanline.png, crt.png, ascii.png, pixel.png or halftone.png. All PNGs are opaque (ASCII has a near-black background).
  • Fit: rectOf(panel) gives the rectangle the picture occupies inside the panel: the whole panel for fill, or the largest centred box with the picture's own shape for whole image. The .stage element (which holds the canvas) is moved to that rectangle, so the effects themselves do not change. A download uses the same rectangle, which is why whole image downloads are uncropped.
  • Compare: a second canvas (canvas.orig) with the plain picture lies on top of the effect and is cut with clip-path: inset(0 X% 0 0); the divider is a thin element at the same position. setWipe(panel, 0..1) moves both.
  • Save all: every panel is drawn off-screen in the shape of the first visible panel (longest side up to 2048px) and the four tiles are placed on one canvas with a small dark gap.

Saved settings and links

  • Settings are saved in localStorage under retro-fx-studio, 300 ms after any change, and restored on the next visit: Fit mode, the chosen sample, and per effect panel the effect, the slider values of every effect, Compare on/off and the divider position.
  • An uploaded or webcam picture is not saved; the next visit starts with the default picture (settings are kept).
  • Copy link puts the visible settings after # in the address, for example #fit=contain&img=3&p1=crt,14,45,3&p2=ascii,100,1&p3=pixel,4,16,gameboy,bayer&cmp=010.
PartMeaning
fitcover (fill, crop) or contain (whole image)
imgSample number 0-3 in the order of the top bar. Left out for an uploaded or webcam picture, which cannot travel in a link.
p1, p2, p3The three effect panels: effect key (scanline, crt, ascii, pixel, halftone), then that effect's controls in the order shown on the page. Checkboxes are 0 or 1; palettes are auto, gameboy, cga, pico8, onebit; dither is none, bayer, fs.
cmpThree digits, Compare on (1) or off (0) per effect panel.
  • On opening a link the settings are applied on top of the saved ones, saved, and the #... part is removed from the address bar, so later changes are not undone by a reload.
  • Every value is checked: numbers are rounded and limited to the slider's range, unknown effect or option names fall back to the default.
  • If you change the order of an effect's controls, old links for that effect will read the wrong values.

Algorithm details

CRT

  • For every output pixel, position is turned into nx, ny in -1..1. With k = curvature / 100 and r2 = nx² + ny², the source position is (nx, ny) × (1 + k·r2) / (1 + k). Positions outside -1..1 are black, which gives the rounded corners.
  • Brightness is multiplied by 0.5 on scanline rows and by 1 - 0.22·r2 (vignette). Every third column boosts one of red, green or blue (×1.2) and dims the other two (×0.86).
  • Glow: the result is shrunk to a tenth of its size, stretched back (which blurs it) and added with 'lighter' blending at glow% × 0.7 strength. This avoids ctx.filter, which older Safari lacks.

ASCII

  • Cell width is W / columns. Rows are round(H / (cellWidth / 0.6)), because a monospace character is about 0.6 as wide as it is tall. So the number of rows follows the panel's shape.
  • The font size is set from the cell size and each character is drawn centred in its cell, so nothing is clipped at the top and the text fills the panel at every slider value.
  • Brightness uses 0.299r + 0.587g + 0.114b. Colour mode draws each character in the cell's colour, lifted so the brightest channel is at least 170.
  • The same characters are kept as plain text (panel.text) for Copy text.

Pixel Art

  1. The picture is drawn into a tiny canvas with one pixel per block; the browser's downscaling averages each block.
  2. Palette "From image": medianCut takes up to 16,384 sample pixels, puts them in one box, and keeps splitting the box with the widest colour spread at its median until there are as many boxes as colours. Each box's average is one palette colour. Fixed palettes: Game Boy (4 greens), CGA (black, cyan, magenta, white), PICO-8 (16 colours), 1-bit (black, white).
  3. Each pixel snaps to the nearest palette colour (squared RGB distance). makeNearest caches the answer per 5-bit-per-channel colour, so it stays fast.
  4. Dither Bayer: a fixed 4×4 threshold pattern is added before snapping; its strength is 255 / cbrt(paletteSize). Floyd-Steinberg: each pixel's rounding error is passed to its right and lower neighbours (7/16, 3/16, 5/16, 1/16).
  5. The tiny canvas is drawn back at full size with image smoothing off.

Halftone

  • The picture is shrunk to one pixel per dot cell. Dots sit on a grid rotated 45 degrees around the centre.
  • Plain mode: dark ink dots on a paper colour, radius cell × 0.72 × sqrt(darkness), so dot area follows darkness. Dark pictures therefore look mostly ink with small paper gaps.
  • Colour mode: dots on black, coloured with the cell's hue at full brightness, radius from the brightest channel.

Edge cases

  • Every picture is loaded into a new Image and the effects redraw from its onload, so an upload always refreshes all panels. A file that is not an image, or fails to decode, shows a short message and keeps the current picture.
  • If the camera is blocked, in use, or the page is not on https, a message is shown and nothing else changes. The live loop uses requestAnimationFrame, so it pauses while the tab is hidden.
  • CRT and Pixel Art with Floyd-Steinberg run a loop over every pixel on the main thread. They are the slowest settings, most noticeable with the webcam on or in a 4096px download.
  • With Fit set to fill, a download uses the panel's current shape; expand the panel first for a wider crop, or switch Fit to whole image for no crop.
  • If storage is blocked (private mode) settings are simply not remembered. If the clipboard is blocked, Copy link shows the address in the message instead.
  • The card pictures on the main page (images/0.webp pixel art, 1.webp colour ASCII, 2.webp CRT, each 1265×411) are effect outputs of the default picture made with this page; make them again if the default picture or the effects change.
  • While a panel is expanded the other three are hidden and are not redrawn; they redraw when you close it.

Customising

  • Default picture: DEFAULT_IMAGE (keep it in the offline manifest). Samples: the SAMPLES list.
  • Slider ranges and defaults: the controls list of each entry in FX. Default effect per panel: DEFAULT_FX.
  • ASCII look: ASCII_RAMP (dark to light), the 0.6 aspect factor, the font string and colours in FX.ascii.draw.
  • Add a palette: add a line to PALETTES and an option to the Palette control in FX.pixel.
  • Add an effect: add an entry to FX with label, controls (type range by default, or select / check) and a draw function. It then appears in every panel's list with working controls, download and reset; no HTML changes are needed.
  • Speed and quality limits: MAX_DPR, MAX_EXPORT, LIVE_FRAME_MS, RESIZE_DELAY at the top of the script.

How it differs from the other projects

The simplest one technically: pure canvas pixel processing with no 3D, no network and no framework.

Main quality

Four-way live comparison: you see the original and three effects side by side while you drag the sliders.
